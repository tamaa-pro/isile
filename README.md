# isile — لوحة تحكم VPN

لوحة ويب خفيفة لإدارة حسابات الاتصال على خادم Ubuntu، تدعم البروتوكولات التالية:

- SSH + WebSocket بدون TLS (المنفذ 80)
- SSH + WebSocket + TLS (المنفذ 443)
- VLESS + WebSocket + TLS (المنفذ 443)
- Trojan + WebSocket + TLS (المنفذ 443)

التطبيقات المستهدفة: HTTP Custom و NetMod.

> **تنبيه شفافية:** جميع الأكواد والملفات في هذا المستودع أُنشئت بالكامل (100%) بواسطة Claude من Anthropic، ولم تخضع لمراجعة أمنية مستقلة. راجعها قبل الاستخدام الفعلي، وجرّبها على خادم تجريبي أولاً، واستخدمها على مسؤوليتك الخاصة.

## المميزات

- لوحة ويب عبر HTTPS على المنفذ 2080 بواجهة عربية.
- إنشاء الحسابات وتعديلها وحذفها لكل بروتوكول.
- حد للترافيك وتاريخ انتهاء، ويُعطَّل الحساب تلقائياً عند تجاوز أيٍّ منهما.
- قائمة حسابات مع بحث وفلترة بالبروتوكول والحالة.
- مراقبة استهلاك كل حساب (رفع وتنزيل) مع إمكانية التصفير.
- روابط جاهزة للنسخ لـ VLESS و Trojan، وبيانات اتصال و Payload لـ SSH.
- عرض حالة الخادم والخدمات، وتغيير كلمة مرور المشرف.
- شهادة Let's Encrypt تُصدر وتُجدَّد تلقائياً للاتصال وللوحة.

## المتطلبات

- خادم Ubuntu بصلاحيات root، ومعمارية x86_64 أو arm64.
- دومين يشير سجل A فيه إلى عنوان الخادم.
- فتح المنافذ التالية في جدار الحماية السحابي (مثل Security Group في AWS): منفذ SSH الخاص بك و 80 و 443 و 2080.

## التثبيت

نفّذ الأمر التالي كمستخدم root:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/tamaa-pro/isile/main/install.sh)
```

سيطلب السكربت:

1. الدومين.
2. البريد الإلكتروني للشهادة (اختياري).
3. اسم المشرف.
4. كلمة مرور المشرف (10 أحرف على الأقل).

بعد الانتهاء افتح `https://الدومين:2080` وسجّل الدخول.

## آلية العمل

- **nginx** يستقبل المنافذ 80 و 443 و 2080 ويوزّع الطلبات داخلياً.
- **Xray** يتولى VLESS و Trojan عبر WebSocket على منافذ محلية فقط.
- **جسر SSH** يستقبل طلبات WebSocket ويمررها إلى sshd المحلي.
- حسابات SSH هي مستخدمو نظام بلا shell، ويُحسب ترافيكهم بقواعد nftables.
- ترافيك VLESS و Trojan يُقرأ من واجهة إحصائيات Xray.
- الخدمات: `vpnpanel` و `vpnbridge` و `xray` و `nginx`.

## الأمان

- كلمة مرور المشرف مشفّرة، والجلسات بكوكي آمن مع حماية CSRF، وحظر مؤقت بعد 5 محاولات دخول فاشلة.
- كل المنافذ الداخلية مرتبطة بـ 127.0.0.1 خلف nginx، وجدار ufw مفعّل.
- يُحجب عن مستخدمي SSH و Xray الوصول إلى الشبكة الداخلية وعنوان بيانات AWS الوصفية.
- مستخدمو SSH بلا shell ولا TTY، ويُسمح لهم بتمرير المنافذ فقط.
- يُتحقق من checksum عند تنزيل Xray.

## ملاحظات

- يُعاد تشغيل Xray عند تغيير حسابات VLESS أو Trojan، فتنقطع اتصالات مستخدميه لثانية ثم تعود. حسابات SSH لا تتأثر.
- إن كان تطبيقك يفحص الشهادة بـ SNI مختلف عن الدومين، فعّل تجاهل التحقق من الشهادة (allowInsecure) في التطبيق.
- مسارات الاتصال: `/vless` لـ VLESS و `/trojan` لـ Trojan، وأي مسار آخر مع ترويسة `Upgrade: websocket` يذهب إلى SSH.

## الإدارة من الطرفية

```bash
systemctl status vpnpanel vpnbridge xray nginx
journalctl -u vpnpanel -f
```
