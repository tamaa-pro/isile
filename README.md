# isile — لوحة تحكم VPN

الإصدار الحالي: **1.4**

لوحة ويب خفيفة لإدارة حسابات الاتصال على خادم Ubuntu، تجمع عدة بروتوكولات في مكان واحد:

| البروتوكول | بدون TLS (المنفذ 80) | مع TLS (المنفذ 443) |
|---|---|---|
| SSH + SSL (اتصال مباشر بدون WebSocket) | ✔ | ✔ |
| SSH + WebSocket | ✔ | ✔ |
| VLESS + WebSocket | ✔ | ✔ |
| VMess + WebSocket | ✔ | ✔ |
| Trojan + WebSocket | ✔ | ✔ |


> **تنبيه شفافية:** جميع الأكواد والملفات في هذا المستودع أُنشئت بالكامل (100%) بواسطة Claude من Anthropic، ولم تخضع لمراجعة أمنية مستقلة. راجعها قبل الاستخدام الفعلي، وجرّبها على خادم تجريبي أولاً، واستخدمها على مسؤوليتك الخاصة.

## المميزات

- لوحة ويب على المنفذ 2080 (HTTPS مع نطاق، أو HTTP بدونه)، بواجهة حديثة متعددة الصفحات ومتجاوبة مع الجوال.
- **الرئيسية:** إحصائيات الخادم المباشرة (المعالج مع نسبة كل نواة على حدة، والذاكرة والقرص والشبكة مع رسوم مصغّرة)، وعدد الحسابات والمتصلين، وإجمالي الاستهلاك، وبطاقة استهلاك الخادم الشهري بمبيان أعمدة يومي قابل للفتح والإغلاق (تحميل أو رفع أو كلاهما، مع أيام الشهر كاملة)، والحسابات حسب البروتوكول، والأعلى استهلاكاً، والتي تنتهي قريباً، وحالة الخدمات، وبطاقة المنافذ (SSH و80 و443 و2080) مع بيان وجود خدمة مستمعة على كل منفذ.
- **الحسابات:** قائمة بحث وفلترة، وإنشاء وتعديل وتعطيل وحذف، ونموذج إنشاء منفصل لحسابات SSH وحسابات V2Ray.
- **الصفحة العامة للحساب:** خيار في الإعدادات (مخفية افتراضياً). عند تفعيله يفتح صاحب الحساب `الرابط:2080/اسم_الحساب` ويرى حالته الحية (الاستهلاك والسرعة والصلاحية والاتصال) دون تسجيل دخول، ولا تُعرض كلمة المرور ولا روابط الاتصال.
- **الإعدادات:** تغيير كلمة المرور، والثيم المظلم (رمادي وأسود) والمشرق، وقائمة ثيمات ملونة (أزرق وأحمر وأخضر وبنفسجي وسماوي وبرتقالي ووردي وذهبي)، والعربية والإنجليزية، واختيار المنطقة الزمنية (الافتراضية منطقة الخادم، أو التوقيت العالمي UTC) لعرض التواريخ وإدخالها، وتبديل العرض بين واجهة الهاتف (الافتراضية) وواجهة سطح المكتب من اللوحة نفسها، وإضافة النطاق وإصدار الشهادة لاحقاً مع عرض عنوان الخادم وتحذير عند عدم تطابق النطاق، وسقف شهري لترافيك الخادم، وإعادة تشغيل الخدمات وتحديث اللوحة وإعادة ضبطها (حذف الحسابات وتصفير الاستهلاك والإعدادات مع إبقاء المشرف والنطاق والشهادة) وإزالتها.
- حسابات SSH وV2Ray (VLESS وVMess وTrojan). في SSH تختار طريقة الاتصال: **WebSocket** أو **SSL** (اتصال SSH مباشر بدون WebSocket)، وفي V2Ray تختار البروتوكول، ثم وضع الاتصال لكل حساب: TLS أو بدون TLS أو الاثنان.
- **SSH SSL** على نفس المنفذين 80 و443 دون منفذ جديد: مع TLS يصل SSH مباشرة مغلّفاً بتشفير TLS عبر 443 (بواسطة stunnel)، وبدون TLS يصل SSH مباشرة غير مشفّر عبر 80. يُميَّز SSH عن بقية الحركة تلقائياً.
- حد للترافيك وتاريخ انتهاء، ويُعطَّل الحساب تلقائياً عند تجاوز أيٍّ منهما.
- مؤشر اتصال لكل حساب: نقطة خضراء نابضة عند وجود اتصال، ورمادية عند عدم وجود اتصال.
- **عدّاد المتصلين وحدّهم (SSH فقط):** لكل حساب SSH عدد المتصلين الآن مقابل الحد (`2 / 3`)، وحقل «حد المتصلين» في نافذة الإنشاء والتعديل (0 = بدون حد). حسابات V2Ray لا تملك عدّاد متصلين ولا حداً (انظر «عدّاد المتصلين» أدناه).
- روابط جاهزة للنسخ لـ VLESS وVMess وTrojan، وبيانات اتصال لـ SSH (و Payload لـ SSH WebSocket، و SNI لـ SSH SSL مع TLS).
- شهادة Let's Encrypt تُصدر وتُجدَّد تلقائياً عند وجود نطاق.
- التثبيت بدون نطاق: اضغط Enter عند سؤال النطاق لتعمل اللوحة والحسابات بعنوان الخادم دون شهادة (HTTP وبدون TLS)، ويمكن إضافة النطاق لاحقاً من الإعدادات.

## المتطلبات

- خادم بنظام (+24) Ubuntu بصلاحيات root، ومعمارية x86_64 أو arm64.
- دومين اختياري يشير سجل A فيه إلى عنوان الخادم (بدونه تعمل اللوحة بعنوان الخادم وبدون TLS).
- فتح المنافذ التالية في جدار الحماية السحابي: منفذ SSH الخاص بك و 80 و 2080، والمنفذ 443 عند استخدام نطاق.

## التثبيت

نفّذ الأمر التالي كمستخدم root:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/tamaa-pro/isile/main/install.sh)
```

سيطلب السكربت الدومين (Enter لتجاوزه واستخدام عنوان الخادم بدون شهادة)، والبريد (اختياري، يُسأل فقط عند وجود دومين)، واسم المشرف وكلمة المرور. ينتهي دائماً برسالة واضحة: نجاح مع رابط اللوحة وبيانات الدخول، أو فشل مع الخطوة والسبب وآخر أسطر السجل. السجل الكامل في `/var/log/isile-install.log`.

## قائمة الإدارة والتحديث

بعد التثبيت اكتب في الطرفية:

```bash
isile
```

- `1` تعديل اسم المشرف وكلمة المرور.
- `2` عرض بيانات اللوحة (الإصدار والرابط والمنافذ وحالة الخدمات وعدد الحسابات). كلمة المرور مخزنة مشفّرة فلا تُعرض.
- `3` إلغاء تثبيت اللوحة بالكامل. تبقى الحزم المثبّتة (nginx وcertbot وغيرها).
- `4` التحديث إلى آخر إصدار من GitHub مباشرة مع الإبقاء على الحسابات وبيانات المشرف والشهادة.

## مسارات الاتصال

- `/vless` و `/vmess` و `/trojan` لحسابات V2Ray، على المنفذ 443 (TLS، مع نطاق) أو 80 (بدون TLS).
- أي مسار آخر مع ترويسة `Upgrade: websocket` يذهب إلى SSH WebSocket.
- اتصال SSH مباشر (SSH SSL) على المنفذ 80 بدون TLS، أو على 443 داخل TLS، بصيغة `النطاق:المنفذ@المستخدم:كلمة_المرور`.

## آلية العمل

```
المنفذ 80  ──► vpnmux ──┬─ يبدأ بـ SSH- ──► sshd              (SSH SSL بدون TLS)
                        └─ غير ذلك ───────► nginx (10080) ──► V2Ray / SSH WebSocket
المنفذ 443 ──► stunnel (يفك TLS) ──► vpnmux ──┬─ يبدأ بـ SSH- ──► sshd   (SSH SSL مع TLS)
                                              └─ غير ذلك ───────► nginx (10443) ──► V2Ray / SSH WebSocket
```

- **vpnmux** (`sshmux.py`) يستقبل المنفذ 80 مباشرة، ويستقبل حركة 443 بعد أن يفك stunnel تشفيرها. يقرأ أول بايتات الاتصال: إن بدأت بـ `SSH-` (أو لم يرسل العميل شيئاً خلال ثانيتين، وهو سلوك عملاء SSH التي تنتظر الخادم) يمرّرها إلى sshd المحلي، وإلا يمرّرها إلى nginx كما كانت. هذا الفحص ضروري لأن SSH المباشر وHTTP يتشاركان المنفذ نفسه، ولا يمكن التمييز بينهما قبل فك TLS.
- **stunnel** يستقبل المنفذ 443 ويفك TLS بشهادة النطاق، ويمرّر عنوان IP الحقيقي للعميل عبر PROXY protocol إلى vpnmux ثم nginx، فيبقى حدّ الطلبات والحظر يعملان على العميل الحقيقي. يعمل فقط عند وجود نطاق وشهادة.
- **nginx** يستمع على منافذ محلية فقط (10080 و10443) خلف vpnmux، بالإضافة إلى لوحة التحكم على 2080 (التي تتولى nginx تشفيرها بنفسها).
- **Xray** يتولى VLESS وVMess وTrojan عبر WebSocket على منافذ محلية فقط، بمدخلين لكل بروتوكول (TLS وبدون TLS) لتطبيق وضع الاتصال لكل حساب.
- **جسر SSH** يستقبل طلبات WebSocket من nginx ويمررها إلى sshd المحلي.
- حسابات SSH (WebSocket وSSL) هي مستخدمو نظام بلا shell، ويُحسب ترافيكهم بقواعد nftables بغض النظر عن طريقة الاتصال.
- ترافيك V2Ray يُقرأ من واجهة إحصائيات Xray.

## عدّاد المتصلين

**SSH (دقيق):** كل اتصال SSH مصادَق عليه تقابله عملية `sshd` تعمل بمعرّف المستخدم نفسه. تعدّ اللوحة هذه العمليات كل ثانية من `/proc`، فيعمل العدّ بنفس الدقة عبر WebSocket وSSL والمباشر، دون اعتماد على عناوين IP. عند تجاوز الحد لثانيتين متتاليتين تُقطع الجلسات الأحدث وتبقى الأقدم. المحسوب هو اتصالات SSH المتزامنة، فإن كان تطبيق العميل يفتح اتصالين للجهاز الواحد فاضبط الحد وفق ذلك. الاتصال الذي ينقطع دون إغلاق سليم يختفي من العدّ خلال نحو 3 دقائق (`ClientAliveInterval` × `ClientAliveCountMax`).

**V2Ray (غير مدعوم):** بروتوكولات V2Ray (VLESS وVMess وTrojan) لا تحمل أي هوية للجهاز، فكل أجهزة الحساب تستخدم المعرّف نفسه، وعميل WebSocket بلا mux يفتح اتصالاً جديداً لكل وجهة، وعنوان IP الذي يظهر للخادم قد يتغير باستمرار (شبكات الجوال، CDN، بروكسيات متغيرة). لهذا لا يوجد عدّ دقيق للمتصلين ولا حد لهم في V2Ray، ولا تعرض اللوحة لها عدّاداً ولا حقل حد. يبقى لكل حساب V2Ray مؤشر الاتصال (نقطة خضراء عند وجود ترافيك) وحد الترافيك وتاريخ الانتهاء. سجل وصول Xray معطّل.
- الخدمات: `vpnpanel` و `vpnbridge` و `vpnmux` و `vpnstunnel` و `xray` و `nginx`.

## الأمان

- كلمة مرور المشرف مشفّرة، والجلسات مؤقتة بكوكي آمن مع حماية CSRF وتنتهي دائماً عند منتصف الليل (بحسب المنطقة الزمنية المضبوطة في اللوحة) فيُطلب تسجيل الدخول من جديد، وحظر مؤقت بعد 5 محاولات دخول فاشلة.
- سياسة أمان للمحتوى (CSP) صارمة، وكل السكربتات والخطوط تُخدَم من نفس الخادم.
- كل المنافذ الداخلية مرتبطة بـ 127.0.0.1، وجدار ufw مفعّل. المنفذان العامان 80 و443 يستقبلهما vpnmux وstunnel، ولا يقبل vpnmux ترويسة PROXY إلا من stunnel على منفذ محلي، فلا يمكن تزوير عنوان العميل من الخارج.
- يحظر vpnmux مؤقتاً أي عنوان يكرّر اتصالات SSH مباشرة قصيرة وفاشلة (30 خلال دقيقة)، بنفس منطق جسر SSH WebSocket، دون التأثير على مسارات V2Ray.
- يُحجب عن مستخدمي SSH و Xray الوصول إلى الشبكة الداخلية وعنوان بيانات AWS الوصفية.
- مستخدمو SSH بلا shell ولا TTY، ويُسمح لهم بتمرير المنافذ فقط.
- يُتحقق من checksum عند تنزيل Xray.
- بدون TLS تكون حركة البيانات غير مشفرة بين الجهاز والخادم، فاستخدمه فقط عند الحاجة.

## ملاحظات

- يُعاد تشغيل Xray عند تغيير حسابات V2Ray، فتنقطع اتصالات مستخدميه لثانية ثم تعود. حسابات SSH لا تتأثر.
- إن كان تطبيقك يفحص الشهادة بـ SNI مختلف عن الدومين، فعّل تجاهل التحقق من الشهادة (allowInsecure) في التطبيق.
- خيار TLS أو WebSocket أو SSL لحساب SSH يحدد بيانات الاتصال المعروضة له، ولا يقيّد المسار فعلياً: مستخدم SSH يستطيع الدخول بأي طريقة متاحة بكلمة مروره، كما كان الحال مع خيار TLS قبل هذا الإصدار.
